# D6 Settings entry and old bookmarks — 29 October 2026

[Master plan](README.md) · [Settings ownership](settings-ownership.md) · [Handoff](d6-handoff.md)

`GET /preferences` now renders the real Appearance category with the shared shell,
navigation, search and category Save/Discard. Cached full-form POST and native
preference contracts remain supported. Reads stay private/no-store and preserve
unrelated/native/unknown values; an external referer cannot redirect this entry.

The default entry includes a finite map of recognized old category, control,
help and array anchors. These lead to owning categories, exact array/SponsorBlock
controls or dedicated masking/identity/admin destinations. The destination's
existing authorization remains authoritative. There are no credential values in
the map. Compact/reduced-image/player-style bookmarks explain their retirement
without resetting their saved compatibility values.

With scripting, the browser replaces the bookmark entry and focuses a field where
supported. Ordinary Back skips an intermediate redirect. Without scripting, or
if the navigation asset fails, the targeted anchor exposes an ordinary link naming
the destination. Unknown/malformed fragments remain inert. Explicit categories
take precedence; managed category navigation removes the entry bridge. A dirty
draft still receives the existing departure warning, and no category/identity
save occurs from bookmark navigation. Dedicated editors retain the existing small
timezone-detection request when a signed-in account has no timezone.

## Evidence and limits

The [entry evidence](review/d6-settings-entry-evidence.json) records 320/320
cumulative desktop cases and 20/20 final focused Chromium/Firefox cases. Final
production fixtures, normal/API-only checks, guarded PostgreSQL entry/receipt/
legacy/native/Settings/admin/chat/channel/identity/contribution routes and source/
documentation checks pass. Four retained Light/Dark/enlarged RTL/no-JavaScript/
failed-asset views were inspected.

The retained full-form controller now verifies the existing POST receipt through
additive fingerprint/profile metadata on the Appearance JSON read. It does not
expect the retired full-form HTML. Normalized arrays/maps and future selections
are projected only after that proof. Cookie failures, foreign profiles and
malformed receipts preserve drafts without an automatic retry. Production native
checks compare receipt fingerprints to both actual account state and a retained
guest cookie. Category controllers continue comparing only their owning values;
unrelated category changes do not invalidate a successful category save.

The cumulative run predates only descriptive fallback labels and the retained
controller's JSON receipt refinement. The final 20 cases, final fixture builds,
production route harness and normal/API-only checks include those refinements.
No broader final-code repository suite is implied. D8 owns consolidation and the
final full repository regressions.

The entry-only anchor links add no requests. The final synthetic account entry
is 96,411 HTML bytes / 8,257 gzip bytes, versus 30,257 / 5,704 for the explicit
Appearance category; other category pages do not carry the bridge. These are
fixture observations, not deployed transfer measurements or a new size budget.

All browser traffic/media and credentials are synthetic and intercepted. The
PostgreSQL container is task-owned and disposable; exact ownership/name/loopback/
idle checks precede any reset. No deployed server, external metadata/contribution
service or physical native client was accessed. All 13 earlier manifests remain
frozen. Full enhancement/filter/mask/lookup/media/Back coexistence and D7–D9 remain
required; D6 is not complete.
