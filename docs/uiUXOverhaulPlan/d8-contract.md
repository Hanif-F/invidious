## Retirement

Account for every runtime template/script/style reference before removing assets.
The shared shell and components become the sole browser presentation; remove the
transitional fallback and obsolete listing/control branches. Retire unused Diary
art/fonts/style, first-party Pure/Ionicons foundations and unused comments,
pagination, form and widget controllers only after their actual consumers are
accounted for. Preserve required Video.js plugins, annotations, VR, captions,
licensing and branding. Remove obsolete CSS classes/config nodes with their last
consumer rather than leave a hidden second interface.

The default Settings GET already opens categories. Its unused old full-form
template and fixture-only script are retirement candidates; preserve ordinary old
POST parsing, receipts, CSRF, unknown/native fields and category isolation in
production tests. Migrate browser tests to the actual owning category or guarded
legacy submission contract. Do not retain an unreachable product interface merely
to satisfy its old selectors.

## Runtime ownership

Repeated setup for the same document/media/config cannot add a second player,
control bar, Settings dialog, chapter/diagnostic/dock owner or keyboard handler.
Keep state on the existing owner, including actual stream/audio/caption identity,
playhead/rate/volume and progress synchronization. Departure/profile/disposal must
retire callbacks and delayed work; cached return must restore only accepted
current-profile work. Preserve the intentional pagehide progress-delivery path.

## Verification and accounting

Retain the initial full-suite attempt and its observed failures. Its repeated
retired-selector timeouts were interrupted after 28 minutes; that is not a
completed baseline or final suite result. Resolve every applicable assertion
against the actual preserved behavior. Then rebuild all
normal/API-only production fixtures and run the complete npm suite, relevant/full
specs, normal/API-only application builds and guarded disposable PostgreSQL
checks. Preserve public/native JSON digests, ownership, concurrency and sensitive
data boundaries. A narrow green subset cannot establish D8 completion.

Measure compressed CSS/JS/icon/font assets and representative requests against
the recorded baseline, explaining capability increases without inventing a byte
threshold. Search runtime code for retired dependencies and duplicate paths.
Review Light/Dark/System, desktop widths, enlarged/RTL/long/incomplete content,
keyboard/reduced-motion/forced-color and loading/empty/error/retry states through
the V01–V36 matrix. Mobile website redesign remains deferred; shared native/media
compatibility remains required.

Document exact commands, source snapshots, phase boundaries, failed phases and
local/upstream/device limits in a new D8 manifest. D9 then reconciles the complete
handbook, requirements and user deployment/cache-refresh/rollback handoff.
