# D7 account, data and standalone contract

[Master plan](README.md) · [Tasks](tasks.md) · [Coverage](coverage.md)

D7 is in progress after the accepted D6 runtime. Its work is local; D8–D9 and
overall acceptance remain pending. Earlier accepted evidence manifests and their recorded sources, logs and images
remain frozen.

## Account and authorization

Use the shared shell, readable forms, explicit labels and ordinary POST actions.
Keep login/registration gates, CAPTCHA, purpose-bound CSRF, current-password
checks, session rotation, role restrictions and direct/legacy routes. Retain the
literal bounded username after rename failures; never re-render submitted
passwords. Explain credential-change revocation and irreversible account deletion.
Deletion failures retain the confirmation page with actionable feedback.

Session rows show issuance and current-session status without displaying raw
credentials or inventing device/IP information. Revocation has an explicit
consequence and an ordinary form. Accept the existing query session parameter for
older callers; the new form carries it in the POST body. Authorization displays
escaped requested scopes, exact callback and expiration; approval preserves scope
and native/custom callback protocols. Cancel goes to the internal session manager.
Malformed/executable callbacks fail before token issuance. Preserve the native Int64 expiration value through browser consent; dates outside the displayable calendar range use the exact timestamp. Issued tokens appear
only in the explicit private token result, never configuration or browser storage.

Optional form enhancement prevents duplicate submits without disabling successful
controls or losing the chosen submitter. It does not fetch, retry, persist drafts
or replay writes. No-JavaScript submission remains complete. Account pages do not
load browsing/enhancement consumers or initiate unrelated preference writes.

## Remaining D7 families

Import selects one existing source and upload field, with an ordinary GET source
choice; export links are grouped by actual format/scope. Explain partial imports,
existing background work and real format limits without adding import capabilities. Parser/import exceptions keep their failure status and selected source form; never echo uploaded contents or create a public issue report from them. Earlier sections can remain committed.
Admin, verification, API-only recovery, legal/message/error and minimal embed
surfaces use shared tokens and appropriate standalone structure. Preserve the
verification bridge, native scopes, privacy headers, licenses and existing player
instance/stream behavior. No password recovery, deployment or upstream access.

## Verification

Use production routes/templates and guarded disposable PostgreSQL for ownership,
CSRF, failure drafts, credential/session changes, callbacks/scopes, deletion and
TV/native compatibility. Inspect light/dark, long text, enlarged/RTL, keyboard and
no-JavaScript forms in Chromium/Firefox using intercepted local fixtures. Record
actual test totals and limits in a new D7 evidence directory. D7 acceptance waits
for every family above; account-only checks cannot establish stage completion.
