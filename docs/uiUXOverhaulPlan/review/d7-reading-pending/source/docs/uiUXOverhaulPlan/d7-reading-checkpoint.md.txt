# D7 reading and error checkpoint

[Master plan](README.md) · [D7 contract](d7-contract.md) · [Coverage](coverage.md) · [Evidence](review/d7-reading-evidence.json)

**Legal, message and HTML error surfaces are locally verified and this evidence
checkpoint is frozen. Minimal embed integration and D8–D9 remain;
D7 as a whole is incomplete. Nothing has been deployed.

## Reading and privacy

Privacy and JavaScript licenses use the shared shell, readable measure, explicit
headings and contained actions. Privacy now describes actual account/library/
history/position/clip/block/chat/identity storage, browser profile isolation,
verification/providers, request/throttle logging and real export/removal limits.
It no longer promises that logout clears local profiles, that only the original
account fields exist, or that network addresses are never processed. Operator
backup/proxy retention and accepted upstream contributions are not represented
as deletable by account removal. The policy remains explicitly English with
appropriate language/direction inside the localized shell.

GET/HEAD legal pages remain readable before required login and bot verification;
the exception does not admit other methods or grant account/content access.
License rows retain the LibreJS table ID, three linked columns, existing vendor
licenses and generated first-party script enumeration. The table scrolls within
the page. Pinned Lucide source and the local Lucide/Feather licenses are linked.
The disabled Popular notice has one heading and structured recovery, without
another feed navigation bar.

## Errors and recovery

Deliberate information errors and unavailable-video reasons are escaped as plain
text. Unexpected errors offer optional technical details containing method, route
pattern, date, exception class and version. Raw request resources/queries, headers,
bodies, exception messages and backtraces do not enter those HTML reports or their
public issue links. Header login/theme actions also omit the failed private query.
Native JSON/Atom error helpers and their schemas are unchanged by this HTML work.

Read retries use validated public identifiers and discard unrelated query fields.
Valid watch GETs retain deliberate alternate-instance/YouTube options using only
the validated video ID. Failed writes offer current-state guidance and relevant
ordinary navigation, with no resubmission form or automatic replay. POST searches
return to Search without exposing or restoring the private query. Embedded errors
use script-free, frame-readable panels and explicit new-window actions. The final
unknown-route fallback reports 404; existing shorthand/branding redirects remain.

Reading errors cannot initialize watch/listing/enhancement consumers or unrelated
timezone/subscription/SSE work. Presentation escapes locale and allowlists color
mode while preserving stored unknown/native preference fields. Errors can render
before preference middleware has populated context.

## Evidence and limits

- **64/64 final Chromium/Firefox cases:** twelve reading/error cases plus the
  existing 52 account/data/verification/recovery cases. Includes Light/Dark,
  1280–1920px, enlarged RTL, no-JavaScript, forced-color keyboard focus, optional
  detail disclosure, license/link coverage, escaped preferences/reasons, native
  unavailable reasons, confidential diagnostics and no replay after cached return.
- **8/8 focused shared-shell/Settings regressions** pass after the integration.
- Guarded production required-login checks pass: actual GET/HEAD legal routes,
  other-method rejection, existing browser/native credentials, scopes/CSRF,
  whitelist, signed feeds and administrator persistence. This phase precedes only
  the final error-heading/read-action/license-attribution refinements; final
  browser/type/fixture checks include them.
- Final normal/API-only type checks, fixture build/render, syntax/format,
  generated references, documentation and whitespace pass. Five final views were inspected.
  Final database guard confirms the exact loopback/task-owned container, account
  schema 24 tables and verification schema six tables, both with no other clients.
- Initial fixture compilation exposed an old raw-HTML error mock; it now calls
  the production helper. Boundary checks passed 8/8. Initial layout phase was 2/4
  because both engines encountered an English-only assertion on a correctly
  Arabic-translated notice. The corrected final matrix passes; phase totals are
  not added together.

All browser traffic/media/providers are synthetic and intercepted; database/HTTP
work stays in owned local fixtures. No deployed server, upstream service or native
device was contacted. Seventeen preceding manifests remain frozen. This does not
claim a new full repository/D6/legacy regression run; D8 owns those checks and
asset/runtime retirement. D9 owns final semantic documentation and requirements
acceptance.
