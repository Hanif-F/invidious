# Settings field ownership and persistence contract

[Master plan](README.md) · [Design contract](design-system.md) · [Progress](progress.md)

D2 is complete. Category services, HTTP handlers, nine server-rendered forms, bounded browser drafts/search/read-back and a separate administrator handler are implemented. The expanded legacy/admin regression run passed; the evidence snapshot is linked from the progress log. The authoritative manifest is [web_preferences.cr](../../src/invidious/web_preferences.cr). This document does not claim category pages are already shipped.

## Category writes

Each write reads the latest raw JSON under the account row lock, validates the owning category, normalizes its values with the existing model, and merges only that category back into the raw document. Unrelated/native/unknown fields are retained. Unknown SponsorBlock map entries are retained too. An omitted checkbox means false only among the submitted category’s booleans; omitted scalar/array fields remain sparse, and omitted array positions retain their latest values. Invalid values reject the whole transaction. Disabling position synchronization clears positions in the same transaction and does not disable history.

## Dedicated endpoint ownership

These fields never enter a general category replacement. Private DeArrow identity remains entirely outside preference JSON and ordinary page configuration.

| channel-visibility | `channel_spoiler_settings` |

Manual channel blocks are stored outside preference JSON and retain their dedicated management/API routes. Chat offsets remain per video; hide-user-ID state remains profile-local. Native overlay data is retained even after browser overlay removal in D6.

The blocked-channel manager reads and mutates only the authenticated owner's
`blocked_channels` rows. Its optional web `format=json` response contains the
canonical channel list, current browser profile and a route-specific CSRF token.
The original contextual `redirect=false` response remains exactly
`{blocked: true|false}`. Native scopes, payloads and preference documents are
unchanged. The optional submitted browser profile rejects stale new forms while
older forms remain compatible.

An explicit Unblock reads fresh state before writing once. Failed rows stay
visible. An ambiguous result disables further mutations until an explicit saved
list check; failed checks retain that uncertainty. A failed list read never
claims the list is empty. Profile/page/removal boundaries invalidate callbacks,
and dispatch invalidates saved browsing previews. Ordinary account forms and
direct channel links remain usable without the manager script. Contextual blocks
hide discovery/Up next only after a valid confirmation, preserve personal library
rows and support confirmed Undo; unknown outcomes offer a reload, never a write
retry.

SponsorBlock's channel endpoint patches only the selected channel in the latest
raw account document with compare-and-set. Inherited values clear its known web
fields while preserving future native properties; explicit Reset removes only
that channel. Its optional web JSON response contains normalized channel values,
the browser profile and a route-specific CSRF token. Guest overrides remain in
the guest browser profile. A successful guest save requires durable read-back;
failed page-memory fallback never earns a Saved notice. Ambiguous account writes
block further mutations until an explicit saved-state check, retaining the draft.
External guest updates change the Discard baseline without replacing dirty
controls. Ordinary account forms retain these endpoint and field names.

Channel masking retains the account row lock but now patches only its selected
raw rule. Other rules, names, future properties and unrelated fields survive.
Opaque selected records reject unsafe edits until an explicit removal; no fields
are silently normalized away. Guest rules require durable storage and preserve
external dirty drafts. Both channel editors reject new entries at the existing
1,000-entry limit while allowing edits/removal, and retain omitted failed-form
semantics. The age input preserves literal whitespace as text; client/server
validation remains bounded whole-day validation.

DeArrow identity has a dedicated account-only Settings destination at
`/preferences/dearrow/identity` and retains `POST /dearrow_identity`. The entered
private ID stays in the live password input only; metadata contains storage
readiness, configured status, profile, endpoint CSRF and an opaque ciphertext
revision. Ordinary failed forms never echo credentials. Conditional web imports
preserve a newer native/web identity; explicit replacement confirmation is
required in the new editor. Older callers and native payloads remain compatible.
Unconfirmed browser writes require a read-only status check, which cannot prove
the imported value; keeping the saved identity explicitly discards the draft.
No private ID enters ordinary preference JSON, page metadata, exports or
application browser storage. Existing encryption and account deletion semantics
remain unchanged.

## Browser-only watch state

`watch_layout` accepts only `standard` or `theater`; `player_dock_enabled` accepts only booleans. They use the existing InvidiousStorage profile, stale-tab guards, deletion cleanup and denied/quota fallbacks. Consumers default to standard/off. Saving account preferences does not import guest state. The player controls and behavior are connected in D5, not by these validators alone.

## Browser forms and verification

`GET /preferences?section=<category>` renders only the owning form. The library category requires an account. Ordinary POSTs redirect to that category; `redirect=false` retains `preferences`/`fingerprint` and adds category values/profile. A separate `format=json` GET supplies canonical read-back. The browser compares the owning values and profile, so an unrelated category change does not invalidate a successful save. Failed, expired or unconfirmed saves retain the draft and offer an explicit reload; they never retry a write automatically.

`GET /preferences` now opens Appearance. Its entry-only compatibility links map
recognized historical group/control/help/array anchors to owning categories or
dedicated editors. Scripts replace that history entry; without scripting a
targeted ordinary link names the current category. Unknown/malformed fragments
are never treated as destinations. Explicit categories win, and switching a
bounded Settings component removes its entry bridge. Retired display bookmarks
explain the unified layout/player appearance; no preference values are reset.

Settings navigation is a bounded component: explicit category selection retrieves the server-rendered category, while at most nine category drafts stay in this document's memory. Search uses field/category metadata locally. URLs remain real GET fallbacks; drafts are never serialized into history or browser storage. Save/Discard affects only the active category. Discard restores its last confirmed page snapshot; leaving with dirty drafts uses the browser's departure warning. Other application links navigate normally. Without JavaScript, normal forms, category links and a reload-based Discard remain available.

Guest writes merge the actual raw `PREFS` cookie. Fresh browsers begin with a sparse document and inherit model/config defaults. An oversized resulting cookie is rejected rather than truncating unrelated data. The subsequent GET detects a browser that did not retain the cookie. Account writes never import that guest cookie.

## Legacy and small writes

The cached full-form POST remains supported. Its retained browser controller verifies the existing receipt through additive `fingerprint`/`browseFingerprint`/profile metadata on the Appearance JSON read; it no longer expects a retired full-form HTML GET. Failed guest cookie retention, foreign profiles and malformed receipts preserve the draft without retrying writes. Current category controllers still compare only their owning values/profile, so unrelated category changes do not invalidate their successful saves. Its traditional checkboxes retain unchecked semantics; omitted scalars, array positions and native-only choices come from the latest stored document. Explicit old native-choice fields remain recognized. A presence marker distinguishes an unchecked legacy reduced-image control from omission. Recognized old AI checkbox groups retain their whole-group semantics, while a version-2 AI form owns the master and canonical actions. Dedicated chat/channel/identity data stays outside this replacement.

Header color-mode and account timezone detection merge only their small patches. These paths and full-form compatibility use transactional compare-and-set with bounded retries after a known database conflict; position cleanup happens only inside a successful transaction. The category handler uses an account row lock. Existing response/redirect contracts remain intact. The four previously retired fields `theme`, `theme_random`, `theme_random_interval_hours` and `theme_random_next_at` still use the existing explicit cleanup; other unknown fields are preserved.

## Instance administration

`/admin/settings` has a separate administrator-only GET/POST handler, current session CSRF, private/no-store responses and revision conflict detection. Personal category and legacy saves ignore instance keys. Declared YAML ownership is `popular_enabled`, `captcha_enabled`, `login_enabled`, `login_required`, `registration_enabled`, `statistics_enabled`, `modified_source_code_url`, plus only `default_home`/`feed_menu` under `default_user_preferences`.

The form reads those keys from the latest configured YAML (using running values for environment-managed fields), and the handler merges those keys into that same authoritative document, retaining unrelated values instead of serializing runtime `CONFIG`. Environment-managed keys are read-only; inline environment configuration cannot be written to a file. Access changes require explicit confirmation, and requiring accounts keeps sign-in enabled. A lock and atomic replacement preserve file permissions and configured symlinks. YAML formatting/comments may normalize. A missing/unwritable file, invalid input or stale revision retains the form draft and reports failure. Verification-provider availability does not gate this authenticated recovery route. Normal/API-only build verification remains part of the later full regression gates.
